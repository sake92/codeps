Export formats 🔗

All exporters receive the final graph: nodes = packages after filtering and collapsing, edges = package dependencies (self-edges removed, deduplicated).

DOT 🔗

Rendered by DotExporter. Graphviz digraph with quoted node ids:

digraph deps {
  "com.example.app" -> "com.example.modules.module2";
  "com.example.modules.module1" -> "com.example.util";
}
  • edges are sorted by (source, target)
  • isolated vertices (no edges) are emitted as standalone lines
  • quotes and backslashes inside package names are escaped

Render it with Graphviz:

deder exec -t run -m cli semdb classes/META-INF/semanticdb -i com.example -f dot -o graph.dot
dot -Tsvg graph.dot -o graph.svg

JSON 🔗

Rendered by JsonExporter. Shape:

{
  "nodes": ["com.example.app", "com.example.modules.module1"],
  "edges": [["com.example.app", "com.example.modules.module2"]],
  "nodeInfo": {
    "com.example.app": {"files": 1, "classes": 1}
  }
}
  • nodes — sorted package names
  • edges — [source, target] pairs, sorted
  • nodeInfo — per-package {files, classes} stats; present only for SemanticDB input (jdeps output carries no file/class info), and only for nodes with known stats

This is the input format of the interactive demo.

Mermaid 🔗

Rendered by MermaidExporter. flowchart LR with aliased node ids (N0, N1, ...) because Mermaid ids break on dots:

flowchart LR
  N0["com.example.app"]
  N1["com.example.modules.module1"]
  N0 --> N1

Nodes are listed first (sorted, each with its N<i> alias and quoted label), then edges as N<i> --> N<j> (sorted by source/target).

Paste into any Mermaid renderer, or embed in Markdown:

```mermaid
flowchart LR
  N0["com.example.app"] --> N1["com.example.modules.module1"]
```
